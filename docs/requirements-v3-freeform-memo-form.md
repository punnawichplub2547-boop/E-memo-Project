### ชีตแถมที่มีค่า

**1. `Sheet1` ของใบ MT = ใบวิ่งงาน (routing slip)** — ตรงกับ paper flow ใน `CLAUDE.md`

```
Detail/Flow Status : Issued >>   Read/Checked >>   Approved
Dept. แผนก         : MT  —  —  PU  HR&GA  ACC/FIN  GM  MD
PIC ผู้รับผิดชอบ   : (ชื่อผู้รับผิดชอบรายบุคคล 1 คนต่อ 1 แผนก — 8 ช่อง)
Duration (3days)   : 1 (same day) … 3 (same day)
Date วันที่ต้องการให้ดำเนินการ
```

⇒ ยืนยันกติกา **3 วันทำการ** และมี **PIC รายบุคคลต่อแผนก** (เกี่ยวโดยตรงกับงาน custom person-based routing ของ V2 ส่วนที่ 1 ซึ่ง**ทำเสร็จแล้ว** — ดู `requirements-v2-intake.md` §1)

**2. `ค่าใช้จ่าย <แผนก>` = สมุดคุมงบรายเดือน** — คอลัมน์ใกล้เคียงหน้า `/report` มาก

`ลำดับ · ฝ่าย · เลขที่ Memo · วันที่ · ประเภทเอกสาร · Account code · เรื่อง · ผู้รับเงิน · งบประมาณที่ใช้ได้ · ยอดเงินที่ใช้ (ไม่รวม Vat 7%) · งบประมาณคงเหลือ · ผู้อนุมัติ · หมายเหตุ`

ทุกแถว `ประเภทเอกสาร = "E-Memo"` · account code ที่ใช้จริงอยู่ในหมวด **`5504xx`** (กลุ่มค่าซ่อมแซม-เครื่องจักร) 3 รหัสติดกัน

## ⚠️ ข้อควรระวังก่อนออกแบบ (สำคัญที่สุดในไฟล์นี้)

**"อิสระ" ชนกับ "กฎอนุมัติอัตโนมัติ"** — เครื่องมืออนุมัติตาม Book1 ต้องการข้อมูล **มีโครงสร้าง** อย่างน้อย: จำนวนเงิน (บาท), แผนก, สถานะงบ, หมวดหมู่ ถ้าเนื้อเมโมกลายเป็น free-form ทั้งก้อน ระบบจะ **route อัตโนมัติไม่ได้** และ Excel export/สมุดคุมงบก็ดึงตัวเลขไม่ได้
⇒ ทิศทางที่น่าจะถูกคือ **แยกสองชั้น**: ฟิลด์โครงสร้างที่ระบบต้องใช้ (เงิน/แผนก/งบ/หมวด) คงไว้ + เนื้อความและตารางประกอบเป็นส่วนอิสระ — **แต่ยังไม่ตัดสิน รอ brainstorm กับคุณพลับ**

**เรื่องต้องตัดสินตอนเก็บ requirement จริง (ยังไม่ถาม อย่าเพิ่งเดา):**

1. "อิสระ" แค่ไหน — เลือกจากบล็อกสำเร็จรูป / สร้างฟิลด์เองได้ / rich text ล้วน?
2. ฟอร์ม ISO F-DC-006 ยังต้องออกได้เหมือนเดิมไหม ถ้าเนื้อหาอิสระแล้วจะ map ลงเซลล์คงที่อย่างไร
3. สกุลเงินต่างประเทศ — กฎวงเงิน Book1 คิดเป็นบาท ใช้เรตวันไหน (วันสร้าง / วันอนุมัติ) ใครเป็นคนกรอกเรต
4. ช่องเซ็นยืดหยุ่นตามแผนก ↔ custom person-based routing (V2 ส่วนที่ 1 ที่ทำเสร็จแล้ว) ทับซ้อนกันแค่ไหน ต่อยอดของเดิมได้เลยหรือไม่
5. สมุดคุมงบรายเดือนให้ระบบออกแทนการพิมพ์มือด้วยเลยไหม
