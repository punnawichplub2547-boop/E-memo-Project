## ✅ ส่วนที่ 1 — Custom Routing บนหน้า Create Memo

**คำขอเดิม:** เลือก route คนส่งเองได้ ลำดับ 1 → 2 → 3 → … → คนอนุมัติสุดท้าย พร้อมบอกตำแหน่งของคนนั้น

**ข้อสรุปที่คุณพลับตัดสินแล้ว:**

| ข้อ | ผลสรุป |
|---|---|
| Q1 | **แยกเป็นแท็บใหม่** ในหน้า create ชื่อทำนอง "Customize route เอง" — แท็บเดิม (แนะนำตาม Book1) ยังอยู่ |
| Q2 | เลือกใครก็ได้ **อิสระ 100%** ไม่มี guard บล็อก |
| Q3 | "ตำแหน่ง" = **`approval_level` ที่มีในระบบอยู่แล้ว** → ✅ ไม่ต้องเพิ่มคอลัมน์/migration ในตาราง `users` |
| Q4 | คนลำดับก่อนสุดท้าย = **"ตรวจ/เห็นชอบ"** · คนสุดท้าย = **"อนุมัติ"** |
| Q5 | **ไม่จำกัดจำนวนลำดับ** ⚠️ (ดู Q21) |
| Q6 | ระบบ **รองรับทั้ง 2 แบบ** (route ตามระดับตำแหน่งเดิม + route รายบุคคล) ให้ผู้ใช้เลือกได้ — เมโมเก่าไม่ต้องแปลง |

**ผลต่อสถาปัตยกรรม:** ระบบต้องรองรับ route 2 ชนิดพร้อมกัน — ของเดิมเก็บเป็น `ApprovalLevel[]` (ระดับตำแหน่ง),
ของใหม่ต้องเก็บรายบุคคล (user id + ชื่อ + ตำแหน่ง + บทบาท ตรวจ/อนุมัติ)
กระทบ: `approval.ts`, `memo-visibility.ts`, `workflow-rules.ts` (`canActOnStep`), `notifyApprovers`,
DB `selected_route_json`, queue drawer/timeline, Excel export, audit log

**ผลพลอยได้:** watch item เดิม *"ถ้า `users.approval_level` ไม่ตรงชื่อ step เป๊ะ จะไม่มีใครได้ notification"*
จะหายไปเองในโหมด route รายบุคคล เพราะยิงตรงที่ user id

## ✅ ส่วนที่ 2 — ตารางเปรียบเทียบราคา: ส่วนลด + บังคับหมายเหตุ

**คำขอเดิม:** แสดงส่วนลดทั้งจำนวนเงินและเปอร์เซ็นต์ · ถ้าส่วนลดเป็น 0 บังคับใส่หมายเหตุ "ไม่สามารถต่อรองราคาได้" หรือทำเป็นปุ่ม

**ข้อสรุปที่คุณพลับตัดสินแล้ว:**

| ข้อ | ผลสรุป |
|---|---|
| Q7 | **% กรอกกลับได้ (two-way)** — พิมพ์บาทได้ % ให้ · พิมพ์ % ได้บาทให้ |
| Q8 | "ส่วนลด 0" = **ผู้ขายไม่ให้ส่วนลดเลย** เรื่องเดียว ไม่ใช่ 2 กรณี → ใช้ `discount` เดิม ไม่เพิ่ม field |
| Q9 | บังคับหมายเหตุ **เฉพาะแถวเจ้าที่ถูกเลือก** (`isSelected`) |
| Q10 | **มีทั้งปุ่มและพิมพ์เอง** — กดปุ่มแล้วเติมข้อความ "ไม่สามารถต่อรองราคาได้" ให้ แก้ต่อได้ |
| Q11 | **ส่งไม่ได้จนกว่าจะใส่ แต่บันทึกร่างได้** |
| Q12 | **บังคับตอนแก้ไขและส่งใหม่ (revision) ด้วย** |

**ผลต่อสถาปัตยกรรม:** งานเล็ก ไม่ต้อง migration — `PriceComparison` มี `discount` + `remark` อยู่แล้ว
และเก็บเป็น `memos.price_comparisons_json` (JSON) จึงเพิ่ม field ใหม่ได้เลย

**สิ่งที่ต้องตัดสินใจเองระหว่างทำ (ไม่ต้องถาม):**

- % คิดจาก **ราคาก่อน VAT** ให้ตรงกับ `computePriceRowTotals` ที่หักส่วนลดก่อนบวก VAT 7%
- **บาทเป็นค่าหลักที่เก็บจริง** ส่วน % เป็นตัวช่วยกรอก → ปัดทศนิยม 2 ตำแหน่ง กันค่าเพี้ยนจากการแปลงกลับไปมา
- แถวที่ยังไม่กรอกราคาเลย (แถวเปล่า) ไม่บังคับหมายเหตุ

## ✅ ส่วนที่ 3 — Short Note แนบไปกับการแจ้งเตือน

**คำขอเดิม:** เพิ่ม short note → ไปโผล่เป็น "เรื่องเพิ่มเติม" ในแจ้งเตือน Outlook + Telegram · แทรกรูปได้ · กดแทรกฟอร์ม Excel ของเมโมนั้นได้

**ข้อสรุปที่คุณพลับตัดสินแล้ว:**

| ข้อ | ผลสรุป |
|---|---|
| Q13 | เป็น **ช่องใหม่จริง** ไม่ใช่ `description`/`closingRemark` — คือ "ข้อความที่ส่งไปกับการแจ้งเตือนเท่านั้น" |
| Q14 | **ไม่ขึ้น**ในฟอร์ม Excel และตัวเมโม — ขึ้นเฉพาะในแจ้งเตือน |
| Q15 | ส่งถึง **ทุกคนใน fan-out** เหมือนแจ้งเตือนปกติ (ผู้ขอ + CC + ผู้อนุมัติ) |
| Q16 | ส่ง **เฉพาะตอนส่งเมโมครั้งแรก** ไม่ส่งซ้ำทุกความเคลื่อนไหว |
| Q17 | แนบ Excel = **ผู้สร้างติ๊กเลือกเอง** ไม่ใช่อัตโนมัติทุกใบ |
| Q17b | **Telegram ไม่แนบไฟล์** — ส่งแค่ปุ่มเปิดในระบบ · ไฟล์ Excel ส่งทางอีเมลอย่างเดียว |
| Q18 | รูป **ไม่เกิน 3 รูป รวมไม่เกิน 10 MB** (เท่าไฟล์แนบเดิม) |
| Q19 | **ข้อความธรรมดา + รูป** พอ ไม่ต้อง rich text → ไม่ต้องมี editor/sanitizer เต็มรูปแบบ |
| Q20 | รับได้ที่ Telegram จะแตกเป็นหลายข้อความ |

**ผลต่อสถาปัตยกรรม:**

- ฝั่งอีเมล ✅ พร้อมแล้ว — `email/client.ts` รองรับ attachments + รูป inline `cid:` (มีเทส ใช้กับโลโก้ CAR อยู่),
  `memoToExcelBuffer` เป็น pure function reuse ได้จาก `/api/memos/[id]/email-excel`
- ฝั่ง Telegram — **Q17b + Q19 ทำให้ไม่ต้องเขียน `sendDocument` และไม่ต้องแปลง rich text** เหลือแค่เพิ่ม `sendPhoto`
  (Telegram ไม่รองรับ `<img>` ในข้อความ) → 1 แจ้งเตือน = ข้อความ + รูป (2 ข้อความ)
- ⚠️ Outlook บล็อกรูปจาก URL ภายนอกโดยดีฟอลต์ → **ต้องฝังแบบ CID เท่านั้น**
- ยังต้อง escape ข้อความผู้ใช้ก่อนใส่ลง HTML ของอีเมล และก่อนส่งเข้า Telegram (`parse_mode: "HTML"`)
  แม้จะเป็นข้อความธรรมดาก็ตาม

### ✅ ลงมือแล้ว — พิสูจน์ end-to-end 2026-08-14

**ที่เก็บของ:** 3 คอลัมน์ใหม่บน `memos` (`notify_note`, `notify_note_images_json`, `notify_attach_excel`)
migration `db/migrations/2026-08-13-add-memo-notify-note.sql` · รูปเก็บที่ `storage/notify-notes/<memoNo>/<uuid>-<ชื่อไฟล์>`
**แยกจาก `storage/attachments/` โดยตั้งใจ** เพื่อไม่ให้รูปไปโผล่ในหัวข้อ "ไฟล์แนบ" ของเมโม (Q14)

**Q14 การันตีเชิงโครงสร้าง ไม่ใช่ด้วยวินัยคนเขียน UI:** `serializeMemoRecord()` (`db-memos.ts`) และ
`src/lib/export/*` ทั้งโฟลเดอร์ **ไม่อ้างถึง 3 คอลัมน์นี้เลย** ⇒ ต่อให้เผลอเขียน UI ผิด note ก็ขึ้นในเมโม/Excel ไม่ได้
ยืนยันจริงแล้ว: `loadMemoForExport()` คืน object ที่ **ไม่มี key `notifyNote` ด้วยซ้ำ**

| ข้อ | ผลการพิสูจน์กับคอนเทนเนอร์ + DB จริง |
|---|---|
| Q13 | ✅ การ์ด "เรื่องเพิ่มเติม / Notification note" บน `/create` แยกจาก description/closingRemark |
| Q14 | ✅ ไม่โผล่ใน `/queue` drawer · `GET /api/memos` ไม่ส่งฟิลด์ `notify*` ออกมาเลย · อ่านเซลล์ .xlsx ครบ 361 เซลล์ ไม่มีข้อความ note |
| Q15 | ✅ เข้า fan-out ปกติ (แจ้งเตือนในระบบ + อีเมล) |
| Q16 | ✅ ส่งครั้งเดียวตอน submit ครั้งแรก — เหตุการณ์ `resubmitted` (revision 2) ไม่มี note ซ้ำ |
| Q17 | ✅ `notify_attach_excel=1` เมื่อผู้สร้างติ๊กเอง |
| Q17b | ⚠️ **ยังไม่ได้ยืนยันสด** — ผู้รับที่ผูก Telegram ไม่ตรงกับผู้รับ note ในรอบทดสอบ และ Telegram ล้มด้วยเหตุ `APP_PUBLIC_BASE_URL=http://localhost` (ปัญหาเดิมที่รู้อยู่แล้ว) · **การันตีจากโค้ด:** ไม่มี `sendDocument` อยู่ในโปรเจกต์เลย และ Excel ถูก push เข้า `emailAttachments` เท่านั้น (`notify-memo-event.ts:175`) ส่วนฝั่ง Telegram วนแค่ `telegramPhotos` ที่สร้างจากรูปล้วน ⇒ ไม่มีเส้นทางโค้ดที่ส่งไฟล์ Excel เข้า Telegram ได้ |
| Q18 | ✅ จำกัด 3 รูป / รวม 10 MB / PNG-JPG (validate ทั้ง client และ server) |
| Q19 | ✅ escape ก่อนลง HTML อีเมล (มีเทสต์ XSS) |
| Q20 | ✅ Telegram ส่งข้อความก่อน แล้วตามด้วยรูปทีละใบ |

**ภาษาไทยไม่เพี้ยน:** ตรวจด้วย HEX จาก DB → 165 bytes / 57 อักขระ ตรงกับที่พิมพ์แบบ case-sensitive
รวมสระ วรรณยุกต์ และเลขไทย (ต้องตรวจแบบนี้ เพราะ PowerShell console แปลงไทยเป็น `?`)

⚠️ **ข้อจำกัดที่รู้ตัว:** `compose.yaml` mount named volume ให้แค่ `/app/storage/attachments`
⇒ `storage/notify-notes/` อยู่ใน layer ของคอนเทนเนอร์และ **หายทุกครั้งที่ rebuild** ในทางปฏิบัติไม่กระทบ
เพราะรูปถูกอ่านไปส่งภายในไม่กี่วินาทีหลังอัปโหลดแล้วไม่มีใครอ่านอีก (และโค้ดข้ามรูปที่อ่านไม่ได้
โดยไม่ล้มการแจ้งเตือนทั้งก้อน) แต่ถ้า deploy ตอนมีคนเปิดฟอร์มค้าง รูปจะหายเงียบ — ยังไม่ตัดสินใจว่าจะ mount เพิ่มหรือรับสภาพ
